# 冰美肌库存管理系统

面向小规模生产制造企业的 Windows 单机仓库管理系统。项目使用 Qt Widgets 开发，以物料、仓库和库位为基础，通过入库、出库、生产领退料、成品入库、调拨和盘点形成库存闭环。

设计重点：库存准确、操作简单、方便追溯，不包含金额、审批流、扫码和大型 ERP 功能。

## 技术方案

- Qt 6.5 或更高版本
- C++17
- CMake
- Qt Widgets
- Qt SQL
- QSQLITE
- Windows 64 位

程序使用本地 SQLite 数据库文件。首次启动时自动建立数据表、基础角色、物料分类和默认管理员；后续启动自动执行增量迁移。业务附件预留为以 BLOB 形式保存在数据库文件中。

默认数据库位置由 `QStandardPaths::AppLocalDataLocation` 决定，通常位于当前 Windows 用户的应用数据目录。

## 已实现的库存原则

- 库存不允许直接人工修改。
- 库存变化必须由业务单据产生。
- 每次变化自动生成库存流水。
- 出库、生产领料和调拨不能造成负库存。
- 单据编号在库存事务内生成。
- 普通出入库和生产单据均支持多物料，整单成功或整单回滚。
- 提交令牌避免重复生成同一张普通、生产、导入或盘点单据。
- 支持按物料、仓库、库位和批次保存余额。
- SN 管理物料的业务数量必须为整数并与 SN 数量一致。
- 生产退料必须关联原领料明细，并受剩余可退数量约束。
- 已生效业务通过反向记录处理，核心服务支持部分撤销。
- 累计成品入库达到计划数量时自动完成生产批次，撤销后自动重算。
- 库存调拨在同一事务中完成来源扣减、目标增加、双向流水和 SN 位置更新。
- 库存盘点保存账面数、实盘数和差异原因，确认时自动形成盘盈/盘亏流水。
- 批次查询汇总当前库存和库位数，并可下钻查看该批次全部库存流水。
- SN 查询展示当前状态、位置、最近单据和关联的完整生命周期流水。
- 业务单据附件以 BLOB 保存到 SQLite，支持下载、软删除和恢复；单文件上限 50 MB。
- 管理员可新增用户、调整角色和启停状态、重置密码；系统阻止停用当前账号和移除最后一个启用管理员。
- 当前用户可修改自己的密码，密码继续使用 PBKDF2-SHA256 加盐保存。

## 旧库存 Excel 导入

“库存Excel导入”页面可直接解析 `冰美肌库存-0629.xlsx` 的现有结构，无需安装 Microsoft Excel。系统读取四张原材料/耗材表和“成品”表的最新库存区段，同物料同批次会合并后预览。

- 正库存可导入，并自动创建数据库中不存在的物料。
- 零库存、斜杠和空数量会跳过；负库存、缺少编码或名称的数据会明确报错且不入账。
- 导入生成“其他入库”类型的期初库存单和库存流水。
- 同一个文件导入到同一个库位时会被重复提交保护拦截。
- Excel 本身不包含可靠的单位和 SN 清单，新增物料单位默认使用“个”，不会自动启用 SN 管理；有批次号的新增物料会启用批次管理。

## 首次登录

首次创建数据库时生成以下账号：

```text
用户名：admin
密码：Admin@123（Debug 测试版本中 admin 可暂时留空密码）
```

正式使用前必须修改默认密码。密码使用 PBKDF2-SHA256 加盐保存。

## 本地构建

示例：

```powershell
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_PREFIX_PATH=C:\Qt\6.10.2\mingw_64
cmake --build build
ctest --test-dir build --output-on-failure
```

当前开发环境已使用 Qt 6.10.2 MinGW 64 位完成构建和全部测试。

## 数据安全

真实库存 Excel、运行中的 SQLite 数据库、WAL 文件和构建产物均被排除在版本库之外。代码仓库只保存导入规则，不会上传真实库存数据。
